# Соответствие OWASP Top 10 (2021)

Для каждого пункта описана реализация в сервисе, указаны соответствующие тесты
или пояснения (включая случаи, когда угроза неприменима и фиксируется принятым
допущением).

## A01:2021 — Broken Access Control

**Реализация.** Двухуровневый контроль доступа:

1. Ролевой — зависимость `require_roles(...)` декларативно ограничивает эндпоинты
   (`admin`, `user`, `auditor`). Например, список пользователей доступен только
   администратору.
2. Объектный — пользователь видит и изменяет только собственные `Item`
   (`owner_id == user.id`); `auditor` имеет доступ только на чтение.

**Тесты:** `tests/test_owasp_rbac.py`.

**Ключевое допущение.** Отсутствие чужих ресурсов возвращает `404`, а не `403`,
чтобы не раскрывать факт существования ресурса (anti-enumeration).

## A02:2021 — Cryptographic Failures

**Реализация.**

- Пароли хешируются **Argon2id** (memory-hard KDF) через `argon2-cffi`; в БД и логах
  никогда не встречается открытый пароль.
- JWT подписывается (`HS256` по умолчанию) и проверяется по allowlist алгоритмов;
  обязательные claims `iss`, `aud`, `jti`, `nbf`, `exp`.

**Тесты:** `tests/test_owasp_crypto.py`.

**Допущения.**

- Секрет `SECRET_KEY` задаётся из окружения и не имеет значения по умолчанию.
- Для прода рекомендуется `RS256`-подпись с keyless-ключами Sigstore (этап 6).
- Защита чувствительных данных в хранилище (encryption at rest) — компетенция
  платформы и на этом этапе не реализуется на уровне приложения.

## A03:2021 — Injection

**Реализация.** Все запросы строятся через SQLAlchemy 2.0 с параметризацией; нет
конкатенации строк в SQL. Поиск использует параметризованный `ilike`. Сырой SQL
``text(...)`` с пользовательским вводом не применяется.

**Тесты:** `tests/test_owasp_injection.py` — вредоносная строка
`'; DROP TABLE ... --` обрабатывается как литерал.

**Допущение.** Командная инъекция (subprocess) в сервисе отсутствует — исходящие
системные вызовы не выполняются.

## A04:2021 — Insecure Design

**Реализация.**

- **Rate limiting** на точках аутентификации и API в целом (slowapi).
- **Строгая валидация входных данных**: `extra="forbid"` (защита от mass
  assignment), ограничения длины, формата (`EmailStr`), минимальная длина пароля.

**Тесты:** `tests/test_rate_limit.py`, `tests/test_input_validation.py`.

**Допущение.** Хранилище лимитов slowapi в проде должно быть вынесено в Redis,
чтобы ограничение действовало на все реплики.

## A05:2021 — Security Misconfiguration

**Реализация.** Явные security-заголовки (`X-Content-Type-Options`, `X-Frame-Options`,
CSP, HSTS, `Referrer-Policy`, `Permissions-Policy`), CORS с явным allow-list, отключение
Swagger UI в `production`, конфигурация только через переменные окружения (без
секретов в коде).

CSP выдаётся по-разному: для API — строгая (`default-src 'none'`), для страниц
документации — только собственные ресурсы (`default-src 'self'`, без внешних CDN).
Ассеты Swagger UI отдаёт сам сервис (пакет `fastapi-offline`, путь
`/static-offline-docs`), поэтому загрузок со сторонних доменов нет.

**Тесты:** `tests/test_security_headers.py`.

**Допущение.** HSTS применяется только поверх HTTPS; при локальном HTTP заголовок
безопасно игнорируется браузером.

## A06:2021 — Vulnerable and Outdated Components

**Реализация.** Зависимости зафиксированы в `uv.lock` (воспроизводимая установка).
Ассеты документации (Swagger UI) не загружаются с плавающего CDN-тега, а поставляются
с зафиксированным пакетом `fastapi-offline` и отдаются сервисом локально. Сканирование
зависимостей (pip-audit, osv-scanner) добавляется на этапе 4 (SCA) и встраивается
в ворота релиза.

**Тест/пояснение.** На данном этапе не автоматизировано; покрывается пайплайном CI
(этап 4). См. [раздел «План этапов»](../README.md#план-этапов).

## A07:2021 — Identification and Authentication Failures

**Реализация.**

- Access-токен с коротким TTL (по умолчанию 15 минут).
- Refresh-токены: долгоживущие (7 дней), хранятся в виде SHA-256 хеша, **ротация**
  при каждом обновлении (старый отзывается), явный отзыв при logout.
- Rate limiting на `login`/`register` против брутфорса/credential stuffing.
- Единые неинформативные сообщения о неверном логине/пароле (anti-enumeration).

**Тесты:** `tests/test_owasp_auth.py`.

**Допущения.** MFA и сброс пароля по почте находятся вне скоупа этапа 1.

## A08:2021 — Software and Data Integrity Failures

**Реализация.** На этапе 1 — проверка целостности JWT, отсутствие `pickle` и
небезопасной десериализации, фиксированный lock-файл.

**Пояснение.** Полноценная цепочка целостности (Cosign-подпись образа, SLSA
provenance, проверка подписи перед деплоем) вводится на этапе 6.

## A09:2021 — Security Logging and Monitoring Failures

**Реализация.** Структурированное логирование structlog (JSON в проде), центральный
процессор ред-акции чувствительных полей (`REDACT`), Prometheus-метрики на
`/metrics`, раздельные health-эндпоинты.

Метрики на этапе 1 — только стандартные HTTP (число запросов, латентность, in-flight,
размер ответа); кастомные бизнес-метрики не добавляются до появления потребителя.
`/metrics` на этапе 1 доступен публично; ограничение доступа (внутренняя сеть,
отдельный порт, auth/mTLS) — задача этапа 5.

**Тесты:** `tests/test_owasp_logging.py`, `tests/test_metrics.py`.

**Допущения.** Сбор (scraping) метрик, дашборды и алертинг — этап 7; сбор и
алертинг по логам (SIEM) — внешняя система, вне скоупа сервиса.

## A10:2021 — Server-Side Request Forgery

**Реализация.** Сервис не выполняет исходящие HTTP-запросы, поэтому SSRF напрямую
неприменима. Для переноса в компоненты с исходящими запросами предоставлена функция
`validate_url_for_ssrf` (отклоняет не-http(s) схемы и резолв во внутренние диапазоны
RFC1918/link-local/loopback).

**Тесты:** `tests/test_ssrf.py`.

**Допущение.** DNS-ребиндинг не покрывается этой функцией; для полной защиты нужен
повторный резолвинг IP на момент соединения.
